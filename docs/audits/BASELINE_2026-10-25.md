## 3. Containment check (PREP-3)

What the repository shows (it cannot show what is actually running):

- A limited-cohort Solana **devnet** testnet is documented as live on a single GCE VM (`docs/GCP_TESTNET_PHASE_A.md`, status 2026-08-09). Devnet SOL has no market value, so P2P and claim drains there cost nothing real. They would still corrupt testnet accounting.
- `docker-compose.prod.yml` defaults `SOLANA_NETWORK` to **mainnet-beta**. Whether that file is deployed anywhere is not visible from the repo. **If it is, the P2P transfer and provider-claim paths were live treasury drains and should be treated as an incident.**
- `PROXYHUB_ZK_ONCHAIN_GROTH16` and `PROXYHUB_ZK_ONCHAIN_GROTH16_READY` default to `false` in `docker-compose.yml`. Good: the vacuous ZK path is not on by default.
- `GATEWAY_DNS_REBIND_CHECK` is `true` in `docker-compose.prod.yml` but off by default in code.
- Prior exposure (`p2p_sent` ledger entries that carry a `tx_hash`) could not be measured: there is no database in this environment. Someone with ledger access should run that count and compare it with treasury outflows.

Important: the Day-1 fixes only take effect once the new `control-api` and `provider-node` builds are deployed. Until then the running testnet still has the old behaviour. If the deployment is reachable by outsiders, either deploy promptly or block `POST /v1/wallet/transfer`, `/v1/provider/claim/prepare` and `/v1/provider/claim/confirm` at the proxy.
