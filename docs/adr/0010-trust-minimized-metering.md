# ADR 0010 — Trust-minimized metering (Wave 5.A)

- **Status:** Accepted (Wave 5.A first slice)
- **Date:** 2026-08-11
- **Related:** [`BC11_GROTH16_PATH.md`](../ops/BC11_GROTH16_PATH.md), [`WAVE5_DECENTRALIZATION_PLAN.md`](../ops/WAVE5_DECENTRALIZATION_PLAN.md), ADR 0007

---

## Context

Wave 4 shipped on-chain Groth16 verification of a **batch header digest**
(`root ‖ session_count ‖ total_bytes ‖ period window`). Byte authority remains the
platform edge gateway (`metering.rs` Ed25519 reports). Claiming “trustless metering”
would be false.

Gaps:

1. Header-only digest does not bind the aggregator’s Merkle leaf set in the public input.
2. Circuit is identity over `Fr(digest)` — soundness binds the digest preimage the
   submitter chose, not physical traffic.
3. Escrow Phase B challenge windows are not usage-leaf disputes.

## Decision

### D1 — Edge remains byte SoT for Wave 5.A

Residential egress metering stays at the gateway for performance. Wave 5.A improves
**cryptographic binding of claimed leaves**, not physical trust.

### D2 — batch-digest-v2 (leaf-hash commitment)

```
leaves_hash = SHA256(leaf_0 ‖ leaf_1 ‖ … ‖ leaf_n-1)   // aggregator order
digest_v2   = SHA256(root ‖ count_le ‖ bytes_le ‖ start_le ‖ end_le ‖ leaves_hash)
public      = Fr(digest_v2)   // same identity circuit as v1
```

Leaf definition unchanged (`internal/zk/prover.go`):

`leaf = SHA256(session_id ‖ total_bytes ‖ period_start ‖ period_end ‖ buyer_sig ‖ provider_sig)`.

### D3 — Same circuit VK; new digest semantics

R1CS is unchanged (identity). Verifying key / `VK_HASH` stay as generated by
`tools/gen-batch-vk`. Sample proof regenerated for a v2 digest. Proof system label:
`groth16-bn254-batch-digest-v2`.

### D4 — Fail-closed aggregator

When `PROXYHUB_ZK_ONCHAIN_GROTH16` is on, refuse settle if leaf hashes are empty or
`len(leaves) != session_count`.

### D5 — Claim language

Allowed: “leaf-committed Groth16 batch”, “on-chain verified batch header + leaf set hash”.

Forbidden: “trustless metering”, “ZK proves real traffic”, “fully decentralized usage”.

### D6 — Deferred

- Dual-sign edge WAL / TEE relays
- On-chain R1CS Merkle verification
- Usage-leaf challenge/dispute UX (distinct from escrow Phase B)
- Multi-operator (ADR 0007 / Wave 5.B)

## Consequences

- Program ix `submit_zk_batch_groth16` gains `leaves_hash: [u8; 32]`; clients must upgrade.
- Devnet program upgrade required before control-api/prover cutover.
- Reputation `verify_usage` path unchanged (still consumes ZKBatchPDA + root match).
